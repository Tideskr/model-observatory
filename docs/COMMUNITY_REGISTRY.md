# 社区模型数据库

## 数据对象

每个模型条目应绑定不可变快照，而不是只绑定可能漂移的公开别名：

- 提供商、模型族、公开别名和已知快照标识。
- 上下文、输出限制、工具调用和推理参数能力。
- 普通与 Native 探针族、适用传输和预期行为范围。
- 概率基线、样本规模、置信区间和失效日期。
- Juice/推理档位映射及其证据。
- schema 版本、评分版本、作者、审阅者和签名。

## 生命周期

```text
draft -> submitted -> auto-check -> community-review
      -> maintainer-review -> beta -> replicated -> stable
                                      \-> revoked
```

- `draft`：仅作者可见。
- `submitted`：内容寻址后不可静默修改。
- `auto-check`：schema、范围、重复、secret 和可复现性检查。
- `community-review`：公开字段 diff 和讨论。
- `maintainer-review`：权限、证据和影响评估。
- `beta`：可用于实验结果，不影响正式评级。
- `replicated`：达到独立来源与覆盖门槛。
- `stable`：可进入正式检测；由发布密钥阈值签名。
- `revoked`：存在安全、数据或方法问题；客户端立即停用。

## 提交流程

贡献者必须提交：

- 机器可读字段 diff。
- 变更原因和影响范围。
- 数据来源、采集时间、工具版本和复现命令。
- 是否由提供商或其关联方提交。
- 涉及真实响应时的脱敏声明。

高影响字段包括阈值、评分权重、概率基线、探针预期、模型别名映射和失效策略。这些字段需要至少两名无利益冲突的维护者批准，并经过独立复现。

## 发布与回滚

- Git 仓库保留人类可审阅源文件，构建产物使用规范化 JSON。
- 每个产物按内容 hash 寻址并附 Ed25519 阈值签名。
- 客户端固定可信根，校验 schema、签名、有效期和撤销列表。
- 更新只能创建新版本，不能修改旧对象。
- 紧急撤销优先于缓存 TTL；恢复必须创建新版本并重新签名。

## 利益冲突

提供商可以提交更正和证据，但必须标记为自报，不能独立批准自己的变更。审核者的关联关系应公开记录；存在直接利益冲突时必须回避。
