# 凭据与 Native 检测披露

## 强制披露文案

Native 模式开始前，界面必须完整展示并要求用户主动勾选：

> Native 检测会将你填写的 API 地址、模型名、API key、探针请求和目标 API 返回发送到本项目服务器，由服务器代为发起 Native 请求。请仅使用短期、限额、可撤销的 key。

普通服务器代理模式也必须说明 API key 会经过项目服务器。不得用“安全检测”等泛化描述替代数据流披露。

## 同意规则

- Native 同意不能预选，且每次会话重新确认。
- 记录同意文案版本、时间和任务 ID，不记录 key 到同意日志。
- 文案或数据保留策略变化后，旧同意失效。
- 未同意时开始按钮不可用。
- 用户可以在发送前查看目标域名、模型、探针数量、预计额度和保留策略。

## 凭据优先级

从推荐到不推荐：

1. 资金或官方额度，由项目创建独立受限账号。
2. 捐赠者自托管执行节点，只返回脱敏观测结果。
3. 短期、限额、限定模型、限定来源 IP 的可撤销 key。
4. 长期原始主密钥，不应作为常规捐赠方式。

## 服务端最低要求

- 使用独立密钥保险库和信封加密，不把凭据写入任务数据库、日志或错误追踪。
- 凭据只在执行时解密到内存；任务结束立即清零引用并撤销临时访问令牌。
- API 出站请求只允许用户确认的 HTTPS 主机，阻止私网、metadata、重定向换域和 DNS rebinding。
- 重定向默认关闭；如确需跟随，不得把 Authorization 转发到不同 origin。
- 限制响应大小、执行时间、并发、模型和最大费用。
- 原始响应默认不保留；调试保留必须单独同意、短期加密并可删除。
- 管理员不能直接读取原始 key；所有解密操作进入不可篡改审计日志。

## 前端显示

- key 输入框只显示末四位，页面状态和本地存储中不保存完整值。
- 捐赠凭据公开页只显示不可逆 HMAC 指纹尾部，不能显示可关联的完整 hash。
- 提交后返回独立撤销令牌；服务端只保存其 hash。
- 清楚区分“本地原型未发送”和“生产环境将发送”，避免虚假安全感。

## Native 架构边界

浏览器和 Cloudflare Worker 不能可靠复刻需要原始 TCP/TLS/HTTP 细节控制的 Native 传输。完整 Native 检测需要受控服务器或隔离执行节点。执行器应按任务启动、无持久磁盘、无横向网络权限，并在结果签名后销毁。
